# Публикация Otti в интернете: Render + Neon

После этих шагов у сайта будет адрес вида `https://otti-xxxx.onrender.com`. Его можно отправить
друзьям: сайт откроется с любого компьютера и телефона.

**Стоимость: 0 ₽.** Оба сервиса бесплатные, и банковская карта не нужна.

**Время:** около 40 минут в первый раз.

## Что нужно знать заранее

- **Render** (render.com) запускает сайт. На бесплатном тарифе сайт «засыпает», если
  15 минут никто не заходит. Первый заход после сна длится около минуты, дальше сайт
  работает быстро. Лимит — 750 часов работы в месяц, этого хватает на весь месяц.
- **Neon** (neon.com) хранит базу данных: аккаунты, XP, словарь, результаты IELTS. Бесплатно
  доступно 0,5 ГБ, этого хватит на тысячи учеников. База тоже засыпает через 5 минут без запросов
  и просыпается сама за доли секунды.
- Вход в оба сервиса — через аккаунт **GitHub**, отдельные пароли не нужны. Номер телефона
  в этой схеме не требуется.
- Ключи (ИИ, база) вводятся только в настройках Render. В код и на GitHub они не попадают.

> Если какой-то сервис откажет в регистрации или попросит то, чего у тебя нет, напиши мне
> текст сообщения. Я подскажу другой вариант.

---

## Шаг 1. Аккаунт GitHub и пустой репозиторий

GitHub хранит код. Render будет брать код оттуда.

1. Открой https://github.com/signup и зарегистрируйся по e-mail. Если аккаунт уже есть — войди.
2. Справа вверху нажми **+** → **New repository**.
3. **Repository name:** `otti`.
4. Выбери **Private** (код увидишь только ты).
5. Галочки «Add a README», «.gitignore», «license» **не ставь** — репозиторий должен быть пустым.
6. Нажми **Create repository**. Откроется страница с адресом вида
   `https://github.com/ТВОЙ_ЛОГИН/otti.git` — он понадобится в шаге 2.

## Шаг 2. Отправить код на GitHub

1. Открой папку проекта `otti` в VS Code, затем **Terminal → New Terminal**.
2. Выполни по очереди. Замени `ТВОЙ_ЛОГИН` на свой логин GitHub.

   ```
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/otti.git
   ```

   ```
   git push -u origin HEAD:main
   ```

3. Появится окно входа в GitHub. Нажми **Sign in with your browser** и подтверди вход.
4. В конце терминал напишет что-то вроде `* [new branch] HEAD -> main`. Обнови страницу
   репозитория на GitHub — там появятся файлы проекта.

**Если что-то пошло не так:**
- **`remote origin already exists`**. Выполни эту команду вместо первой, затем снова `git push -u origin HEAD:main`:
  ```
  git remote set-url origin https://github.com/ТВОЙ_ЛОГИН/otti.git
  ```
- **`Author identity unknown`**. Выполни две команды (со своими данными), затем повтори push:
  ```
  git config --global user.name "Tagir"
  ```
  ```
  git config --global user.email "твой@email"
  ```
- **`detected dubious ownership`**. Выполни команду, которую подскажет сам терминал
  (она начинается с `git config --global --add safe.directory`), и повтори push.

## Шаг 3. База данных Neon

1. Открой https://neon.com → **Sign up** → **Continue with GitHub**.
2. Создай проект:
   - **Project name:** `otti`;
   - **Postgres version:** оставь предложенную;
   - **Region:** **AWS Europe Central 1 (Frankfurt)** — рядом с сервером Render, так сайт работает быстрее.
3. Нажми **Create project**.
4. На главной странице проекта нажми **Connect**. Откроется окно со строкой подключения.
5. Включи переключатель **Connection pooling** → **Copy snippet** (или значок копирования).
   Сохрани строку в Блокнот с подписью `DATABASE_URL`.
6. Выключи **Connection pooling** → снова скопируй строку. Сохрани её с подписью
   `DATABASE_URL_UNPOOLED`.

Обе строки начинаются с `postgresql://` и содержат пароль. **Никому их не показывай**
и не присылай в чат.

## Шаг 4. Сайт на Render

1. Открой https://render.com → **Get Started** → **GitHub**. Разреши Render доступ.
2. Вверху нажми **New +** → **Blueprint**.
3. Нажми **Connect GitHub** (или **Configure account**). Выбери **Only select repositories** →
   `otti` → **Install**.
4. Выбери репозиторий `otti` → **Connect**.
5. Render прочитает файл `render.yaml` и покажет сервис **otti** (тариф Free). Заполни поля:
   - `DATABASE_URL` — первая строка из шага 3 (с pooling);
   - `DATABASE_URL_UNPOOLED` — вторая строка;
   - `ADMIN_EMAILS` — e-mail, с которым ты будешь регистрироваться на сайте.

   `BETTER_AUTH_SECRET` Render создаст сам.
6. **Blueprint Name:** `otti` → **Deploy Blueprint** (или **Apply**).
7. Открой сервис **otti** → вкладка **Logs**. Первая сборка идёт 5–10 минут. В конце появятся:
   ```
   ✓ База данных Neon: таблицы в порядке
   ```
   и `Your service is live 🎉`.
8. Вверху страницы сервиса есть адрес `https://otti-….onrender.com`. Открой его.

## Шаг 5. Проверить сайт

1. Открой `https://otti-….onrender.com/status`. Все строки должны быть зелёными.
   Строка ИИ покажет «Тестовый режим»: так и должно быть до шага 6.
2. Зарегистрируйся с e-mail из `ADMIN_EMAILS`. Пройди знакомство и первый урок.
3. Снова открой `/status`. Теперь ты видишь подробности и кнопку «Проверить связь с Отти».
4. Отправь адрес другу. Он регистрируется сам, и его прогресс хранится отдельно.

## Шаг 6. Включить настоящий ИИ

Пока в `render.yaml` стоит `AI_PROVIDER=mock`: Отти отвечает заготовками и ничего не тратит.
Когда будешь готов:

1. Render → сервис **otti** → **Environment** → **Edit**.
2. Для OpenRouter-совместимого сервиса (например, crouter.net) добавь или измени строки:

   | Key | Value |
   |---|---|
   | `AI_PROVIDER` | `openrouter` |
   | `OPENROUTER_API_KEY` | **новый** ключ (старый, который был в чате, нужно отозвать) |
   | `OPENROUTER_BASE_URL` | `https://crouter.net/v1` |
   | `OPENROUTER_MODEL` | название модели, например `claude-fable-5-1` |

   Для GigaChat: `AI_PROVIDER` = `gigachat`, `GIGACHAT_AUTH_KEY` = ключ авторизации.
3. **Save, rebuild, and deploy** (или **Save changes**). Сайт перезапустится за несколько минут.
4. `/status` → «Проверить связь с Отти» должен ответить.

**Запасной провайдер (по желанию).** Добавь `AI_FALLBACK_PROVIDER` и ключ второго провайдера.
Если основной не ответит даже после повторов, Отти спросит запасного.

**Экстренно выключить ИИ:** `AI_ENABLED` = `false` → сохранить. Уроки, словарь, Reading
и Listening продолжат работать.

## Как обновлять сайт

После любых изменений в коде:

```
git add .
```

```
git commit -m "Обновление"
```

```
git push
```

Render заметит изменения и сам опубликует новую версию за 5–10 минут. Таблицы в базе
тоже обновятся сами.

## Частые проблемы

| Что видно | Что делать |
|---|---|
| В Logs: `✗ На Render не задана переменная DATABASE_URL` | Environment → добавь `DATABASE_URL` и `DATABASE_URL_UNPOOLED` из Neon → Save → **Manual Deploy → Deploy latest commit** |
| В Logs: `password authentication failed` | Строка из Neon скопирована не целиком. Скопируй заново (шаг 3) |
| Сайт открывается около минуты | Он «спал». Это особенность бесплатного тарифа |
| В Logs: `JavaScript heap out of memory` при сборке | Environment → добавь `NODE_OPTIONS` = `--max-old-space-size=1536` → Save, rebuild, and deploy |
| Не получается войти после публикации | Проверь, что открываешь адрес `…onrender.com`, а не старый. Если подключал свой домен, задай `BETTER_AUTH_URL` |
| Чат: «Сервер ИИ временно недоступен» с кодом | Logs → поиск по коду (`req=…`): рядом написана причина |
| Страница `/status` красная | Сделай снимок экрана и пришли мне |
